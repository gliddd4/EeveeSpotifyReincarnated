# Metadata Editor — Build Plan (Theos-free, GitHub Actions)

Build plan for the in-app metadata editor for local files, scoped to the four
editable fields: **song name (title), artist, album, album cover art**.

Hard constraints:
- **No Theos on the dev machine.** All builds run in GitHub Actions; Theos
  (where still used for the tweak) exists only on CI runners, never on the
  MacBook.
- **Audio bytes are never rewritten.** Metadata lives in a separate region of
  the file (ID3v2 tag / `moov.udta.meta.ilst`), so editing it leaves duration
  bit-identical — the `spotify:local:artist:album:title:duration` URI stays
  valid and playback is unaffected. Any re-encode approach
  (`AVAssetExportSession` AppleM4A preset) is rejected: lossy, duration drift.

## 1. New module: `MetadataTagKit` (pure Swift, zero dependencies)

Vendored under `Sources/EeveeSpotify/Dependencies/MetadataTagKit/` (same
pattern as `XMLCoder`). Foundation-only → host-compilable for unit tests.

```
Dependencies/MetadataTagKit/
  FormatDetector.swift          sniff ID3 / ftyp → pick codec path
  TagEditor.swift               top-level API: read(url), write(url, edits)
  Models/TrackMetadata.swift    struct { title, artist, album, artwork: Data? }
  ID3/ID3v2TagParser.swift      syncsafe ints, header, frame walk
  ID3/ID3v2TagWriter.swift      rebuild tag + padding, in-place or file rewrite
  ID3/ID3v2TextEncoding.swift   ISO-8859-1 / UTF-16(+BOM) / UTF-16BE / UTF-8
  MP4/MP4BoxReader.swift        generic 4cc box walker (size / 64-bit largesize)
  MP4/MP4BoxWriter.swift        box writer with size back-patching
  MP4/M4AIlstEditor.swift       moov→udta→meta→hdlr+ilst read & rebuild, covr
  MP4/M4AChunkOffsetRebuilder.swift  stco/co64 update when moov grows
```

Fields and their on-disk locations:

| Field | MP3 (ID3v2) | M4A (MP4 ilst) |
|---|---|---|
| title | `TIT2` | `©nam` (data atom type 1 = UTF-8) |
| artist | `TPE1` | `©ART` |
| album | `TALB` | `©alb` |
| cover | `APIC` (enc + MIME + pic-type 3 + desc + image) | `covr` (data atom 13 = JPEG, 14 = PNG) |

Rules: preserve every frame/ilst item we don't edit, verbatim. Writer emits
clean ID3v2.3 text (UTF-8, enc byte 3) unless the file is already v2.4, in
which case preserve the version. Keep ≥ 1KB padding after the ID3 tag and a
`free` box after `moov` where possible so edits fit in place.

## 2. Host-side tests (no device, no Theos)

`Tests/MetadataTagKitTests/` as a SwiftPM test target, run by `swift test` on
`macos-latest` — pure host code, Theos-free by construction.

Fixtures: generated by `ffmpeg` in CI (mp3 + m4a, with and without pre-existing
tags). Assertions:
- round-trip through our own reader;
- cross-check via `ffprobe` (title / artist / album / APIC / covr);
- audio region byte-identical before/after the edit;
- ID3 syncsafe + UTF-16 BOM + oversized-tag → rewrite path;
- M4A moov-grow → mdat move → `stco`/`co64` offset rewrite path.

## 3. Tweak integration (device-side hooks)

Pipeline uses the branch's already-verified seams:

1. Enumerate the Local Files list via `FTPAllSongsDataSource`
   (`trackNameForIndexPath:` / `artistNameForIndexPath:` /
   `albumNameForIndexPath:` / `trackURIForIndexPath:`).
2. Resolve `localFileURLForMediaURL:` (`BetamaxOfflineSDK.OfflineManagerImpl`)
   → on-disk file path.
3. Write through `MetadataTagKit.write(url:edits:)`.
4. Surface:
   - **Cover art** refreshes automatically — `SPTLocalAVAssetImageLoaderRequest`
     reads it live from the file via AVAsset on every request.
   - **Title/artist/album** need display interception (option (a) from
     `MetadataEditor-BulkAddByAlbum.md`): overlay edits in the
     `FTPAllSongsDataSource` getters plus `SPTPlayerTrack.metadata()` /
     `trackTitle()` / `artistName()`, keyed off the tweak-side edit store
     (the `UserDefaults+Extension` already in the branch diff). This survives
     core updates and avoids URI churn.

New file: `Sources/EeveeSpotify/MetadataEditor/MetadataEditorHooks.x.swift`
(Orion). UI entry: a "Edit metadata" row action + a form in
`EeveeSettingsView` (plain SwiftUI/UIKit, no Theos involvement).

## 4. Build & CI

Theos is never installed or run on the dev MacBook. All builds happen in
GitHub Actions:

- **Test job (`test-tagkit`, `macos-latest`)** — new, runs `swift test` on
  `MetadataTagKit` (pure host Swift, no device, no toolchain tricks). Runs on
  every push to this branch.
- **Tweak build** — the existing `.github/workflows/buildpatched.yml` /
  `buildnopatch.yml` pipeline stays as-is: Theos is installed on the GitHub
  runner (it never touches the MacBook), `make package` produces the deb,
  `cyan`/`ipapatch` produce the IPA. The metadata editor hooks and UI are
  regular Orion `.x.swift` sources, so they slot into the existing
  `EeveeSpotify_FILES` glob with zero workflow changes.
- **IPA smoke test** — `workflow_dispatch` with `ipa_url`, reusing the current
  `package-ipa` steps; device testing happens against these CI-built artifacts.

Substrate/ElleKit: not a concern. The shipped IPA bundles `Orion.framework`
+ `CydiaSubstrate.framework` in-app (Orion links substrate weak), and Theos on
the runner produces the same artifacts today — nothing about the metadata
editor changes this.

## 5. Risks & mitigations

1. **M4A moov growth → mdat move → `stco`/`co64` rewrite**: covered by
   dedicated unit tests; padding keeps the move rare in practice.
2. **ID3v2.4 syncsafe frame sizes + unsynchronisation flag**: parser must
   handle both; writer emits clean v2.3 unless input was v2.4.
3. **Non-MP3/M4A local files (FLAC/WAV/OGG)**: out of scope for v1;
   `FormatDetector` fails fast with a clear error.
4. **Spotify cache staleness** for title/artist/album: solved by display
   interception (option (a)), never by forcing a re-scan (URI churn).

## 6. Milestones

- **M1** — `MetadataTagKit` + tests green on macOS via `swift test`.
- **M2** — macOS CLI harness `Tools/metadata-edit` for manual file testing.
- **M3** — tweak hooks (FTPAllSongsDataSource + OfflineManagerImpl + display
